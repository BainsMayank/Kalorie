**Nutrient requirements (not food data).** *Short Report of Nutrient Requirements for Indians —
RDA and EAR 2020*, ICMR-National Institute of Nutrition, `data/raw/ICMR-NIN.pdf` (27 pages).
Typed into `src/lib/targets/icmr.ts` with the printed page number beside every value (PDF page =
printed page + 3). Its copyright page (p. ii) encourages "use and dissemination of the data and
information … with full acknowledgment of the source", **but** also says no part may be
"reproduced in any print, copy or electronic format for creating a product without the prior
written permission" of ICMR-NIN. Kalorie uses only the numbers (requirements are facts, typed in,
the PDF itself is not shipped or committed) and will credit ICMR-NIN on the About screen —
**before the public release (Stage 12), confirm with ICMR-NIN (nin@nic.in) or get advice that this
is fine.** It replaces the unchecked starting values that were in
`data/curated/rda_icmr_nin_2020.csv` / the `rda_reference` table (removed in db_version 3).

`data/raw/` is not committed to git (it's large). To rebuild on another computer, download the
files above into `data/raw/` with the same folder names.

## Open licence questions (answer before the public release, Stage 12)

Code libraries are fine: every npm package is MIT, ISC, Apache-2.0, BSD or similar; the few
others are dual-licensed (node-forge, xdate — we use them under BSD / MIT) or build tools that
aren't shipped in the app (lightningcss, MPL-2.0). Checked 2026-09-28 with `package-lock.json`,
re-checked 2026-10-05. Their notices ship with the app on **About → Open-source licences**,
generated by `npm run build:licences` (re-run it after changing libraries; a test fails if a
dependency is missing from the list).
The data needs three answers:

1. **INDB (Anuvaad).** No licence is published for the database itself. Ask Anuvaad Solutions
   (contact form on anuvaad.org.in) to confirm Kalorie may ship the INDB values in a free app,
   and how they'd like to be credited. Until then the About screen cites their paper.
2. **IFCT 2017 (ICMR-NIN).** Same situation as the ICMR-NIN requirements below: NIN holds the
   copyright on the numbers, whatever licence the npm package has. INDB is itself built mostly
   from IFCT, so this covers most of foods.db.
3. **ICMR-NIN 2020 requirements** (below): the "no reproduction for creating a product without
   written permission" line.

One letter to ICMR-NIN (nin@nic.in) can cover 2 and 3: a free, ad-free app for family and
friends, using IFCT 2017 values and the 2020 requirement tables, with full credit on the About
screen and no copy of either document shipped. **Both emails are drafted in
`data/permission-requests.md`** (2026-10-05), with a table to note when they were sent and
answered. They also ask about the public GitHub repo: `assets/db/foods.db` is committed there,
so it holds the INDB and IFCT values too — if either says no to that, stop tracking foods.db
in git (and rewrite history) rather than only removing it from the app.

Decision (2026-10-05): keep INDB, IFCT and the ICMR-NIN tables and ask permission, rather than
remove them. There is no openly licensed Indian dish database to replace them with — removing
INDB + IFCT would drop 1,528 of the 8,907 foods, nearly every Indian one. Internal testing on
Play (family and friends) goes ahead meanwhile; the public listing waits for the answers.

**Open Food Facts** is settled (ODbL, attribution shown). One thing to keep in mind for Stage 11:
a product found on Open Food Facts that is shared into a group's food pool is still ODbL data —
keep the "Food data from Open Food Facts (ODbL)" line with it.

## Notes on each source

**INDB.** One sheet, 82 columns: nutrients per 100 g plus the same nutrients per serving.
INDB has no
serving weight column, so the build works it out as serving kcal ÷ kcal per 100 g × 100.
It has no trans fat, iodine or vitamin B12 (stored as unknown). Its `vita_ug` is retinol only,
so carotenoids ÷ 6 are added to get vitamin A, with **ICMR-NIN 2020's 6:1 for β-carotene**
(12:1 only for α-carotene and β-cryptoxanthin; short report p. 10 — Stage 9; it was ÷ 12 before).
INDB's **vitamin D is stored as unknown** (Stage 9): it is added up from IFCT's ingredient values,
including IFCT's vitamin D in plant foods (see IFCT below), so soya bean curry showed 34 µg and
pomegranate raita 25 µg a portion.
Known slips still in INDB rows (not fixed, and kept out of `common_foods.csv`): *Black forest
gateau* 219 mg vitamin C per 100 g, *Fried fish (Indian style)* 85 mg vitamin E per 100 g.

**INDB recipes.** One row per ingredient: dish code, ingredient code and name, amount and a
normalised unit (g, tsp, tbsp, ml, C = cup, sprig…). Amounts become grams with tsp 5 ml,
tbsp 15 ml, cup 240 ml and the ingredient's density. About half the ingredients use IFCT codes;
the rest use Anuvaad's own codes (T508 sunflower oil, G528 salt…, copied from the UK CoFID and
USDA tables), whose nutrients we don't have — `data/curated/indb_ingredients.csv` links them to
foods in foods.db (98% of rows are linked; every fat must be). A check in the build shows INDB's
per-100 g values are recipe totals ÷ **raw** ingredient weight (for 82% of dishes the ingredient
kcal match within ±5%), which also confirms the unit conversions. So `foods.yield_g` is the raw
recipe weight, and INDB values assume no water is lost in cooking — a boiled-down dish may be a
little denser in real life than its per-100 g figure.

**IFCT 2017.** The npm package `ifct2017` changed from MIT to **AGPL-3.0** in version 2.1.0
(September 2026). We use `@ifct2017/compositions@2.0.9` instead: MIT-licensed, and the numbers
are identical (all 542 foods × 20 key nutrients compared, 0 differences). It is pinned to the
exact version in `package.json` so an update can't bring in AGPL code by accident.
Every value in that package is in grams per 100 g (energy in kJ), and a missing value is written
as 0, so a nutrient group that is entirely 0 for a food is stored as unknown. The 14 oils and
fats have no energy value; it is estimated from fat (9 kcal/g). 28 numbered varieties
("Brinjal-1" … "Brinjal-21", "Chillies, green-1" …) are skipped because IFCT also gives an
"all varieties" average. No iodine or vitamin B12. Vitamin A = retinol + `cartbeq` ÷ 6
(`cartbeq` is β-carotene equivalents, so this is exactly ICMR-NIN's 6:1 / 12:1).
Two slips fixed in the build (`fixIfctSlips`, Stage 9, found by checking nutrient ranges):
- **Fish vitamin B6 and biotin are 1000× too big** (B6 averaged 131 mg per 100 g; fish has
  0.1–0.9 mg, and 100 mg a day is the safe upper level). Divided by 1000 for the 117 fish.
- **Vitamin D in plant foods** (curry leaves 117 µg, pomegranate 109 µg, soya bean 70 µg per
  100 g) isn't believable — plants other than mushrooms have next to none. Stored as unknown for
  every food that isn't fish, egg, meat, poultry, dairy or a mushroom.
Liver biotin (beef 1,744 µg) also looks high but is left as is (rarely eaten).

**USDA.** Only the foods in `foundation_food.csv` / `sr_legacy_food.csv` are used (Foundation's
`food.csv` also holds lab samples and older versions). Left out: Baby Foods, American
Indian/Alaska Native Foods, Quality Control Materials, Branded Food Products and Restaurant
Foods, and 72 Foundation foods that have no energy value and too few macros to estimate one.
Vitamin A uses ICMR-NIN's factors (retinol + β-carotene ÷ 6 + (α-carotene + β-cryptoxanthin) ÷ 12)
whenever USDA lists retinol and β-carotene; otherwise USDA's own RAE (which uses 12 and 24).

## Hand-kept files (`data/curated/`)

| File | What it holds |
|---|---|
| `synonyms.csv` | Search synonyms: Hindi, spelling variants, regional and English names (591 terms) |
| `category_units.csv` | Units offered, default unit and density for each food category |
| `unit_weights.csv` | Per-food units: roti S/M/L, piece weights (egg, banana…), default-unit fixes |
| `densities.csv` | Density fixes for foods unlike their category (flour, ghee, honey…) |
| `duplicates.csv` | Duplicate decisions the automatic name matching can't make |
| `indb_ingredients.csv` | Links Anuvaad's own recipe-ingredient codes (oils, salt, sugar…) to foods |
| `category_overrides.csv` | Fixes for foods the category rules get wrong |
| `indb_servings.csv` | Piece counts for INDB recipes whose own count is off (gulab jamun, chhena sweets) |
| `search_pins.csv` | The food shown first for an exact everyday search word (dahi → plain yogurt) |
| `thalis.csv` | The 6 built-in starter thalis and their usual amounts |
| `slot_suggestions.csv` | Starter foods per meal slot, shown until the person has their own |
| `common_foods.csv` | ~80 everyday foods with an everyday portion: "Good sources" on the Nutrients screen (Stage 9) |
